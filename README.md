# SIH26162 — Thermal Anomaly Classifier

Classify satellite-detected thermal anomalies (fires/hotspots) across India into
**Industrial Fire, Gas Flare, Wildfire, Agricultural Burning, Other/Unknown** —
with calibrated probabilities, human-readable evidence, and a live map dashboard.

Backend: FastAPI + XGBoost (geographic split, Platt calibration, SHAP explanations).
Frontend: React + Vite + Leaflet map dashboard.

---

## Features

- **FIRMS ingestion** — parses real NASA FIRMS VIIRS-375m / MODIS CSV exports
  (column aliases, l/n/h confidence, daynight flags, acq timestamps). Upload via
  `POST /api/upload-firms` and it is classified live.
- **Real ML pipeline** — XGBoost with geographic 50 km block split (no spatial
  leakage), class weights, Optuna tuning (30 trials), Platt calibration, SHAP.
  Test Macro-F1 ≈ 0.95.
- **Explainable predictions** — calibrated top-3, signed SHAP evidence,
  why-not-runner-up, priority rules.
- **Facility gazetteer** — ~25 actual refineries / steel / mining sites with
  haversine distance to each hotspot.
- **Interactive dashboard** — map of detections, filters, live status banner,
  detail panel with probabilities, evidence, nearest facility and priority badge.

## What is real vs synthetic

| Component | Status | Notes |
|---|---|---|
| FIRMS ingestion (`app/data/firms.py`) | **Real structure** | Parses actual FIRMS VIIRS-375m / MODIS CSV exports. Upload real data via `POST /api/upload-firms` and it is classified live. |
| XGBoost pipeline (`app/ml/train_model.py`) | **Real ML** | Geographic 50 km block split, class weights, Optuna tuning (30 trials), Platt calibration, SHAP. Test Macro-F1 ≈ 0.95. |
| Inference + explanations (`predict.py`, `explain.py`) | **Real** | Calibrated top-3, signed SHAP evidence, why-not-runner-up, priority rules. |
| Facility gazetteer (`app/data/facilities.py`) | **Real names/coords** | ~25 actual refineries/steel/mining sites, haversine distance. |
| Training labels & features | **Synthetic** | `training_data.csv` (3,300 rows) is generated by `app/data/generate_synthetic_data.py` with class-conditional distributions + deliberate overlap. Labels are modelled, not observed. |
| Demo map seed (`app/data/demo_seed.py`) | **Synthetic** | 48 detections anchored to real regions (Gujarat refineries, Odisha mining, Punjab/Haryana stubble belt, Uttarakhand/Himachal forests). The UI shows a "Demo data" banner until real FIRMS data is uploaded. |

## Quick start

### Development mode (hot reload) — two terminals

```bash
# Terminal 1: backend API on :8000
cd backend
python -m venv .venv                      # only once
.\.venv\Scripts\Activate.ps1              # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt           # only once
python start.py

# Terminal 2: Vite dev server on :5173 (proxies /api to :8000)
cd ../frontend
npm install                               # only once
npm run dev
```

Open http://localhost:5173 — Vite serves the dashboard with hot reload and
forwards all `/api` requests to the backend, so no CORS or URL config is needed.

### Local single-server mode (optional)

Build the frontend once and let FastAPI serve everything on :8000:

```bash
cd frontend && npm run build              # outputs to frontend/dist
cd ../backend && python start.py          # http://localhost:8000 = dashboard + API
```

On first run, `start.py` generates `training_data.csv` and trains the model
(~1–2 min); artifacts are cached in `app/ml/artifacts/` so later runs start fast.

## Deployment

Two services, one URL each:

| Service | Platform | What |
|---|---|---|
| `frontend/` | **Vercel** | Static Vite dashboard (Vercel auto-detects Vite) |
| `backend/` | **Render** | FastAPI + XGBoost API (Python needs a real server; Vercel's 250 MB serverless limit can't fit the ~450 MB ML stack) |

### Backend → Render (deploy first, you need its URL)

1. <https://dashboard.render.com> → **New → Blueprint** → select this repo.
   `render.yaml` creates one API service (build: `pip install -r requirements.txt`,
   start: `python start.py`, health check `/health`).
2. Add an environment variable `CORS_ORIGINS` = your Vercel URL(s),
   e.g. `https://sih-26.vercel.app` (comma-separated for multiple).
3. Note the service URL, e.g. `https://sih26162-classifier-api.onrender.com`.

Model artifacts (`model.pkl`, `calibrator.pkl`, `training_data.csv`) are committed
so the service boots instantly — no retraining on deploy or cold start.
On the free tier the service spins down after ~15 min of inactivity (~30 s cold start).

### Frontend → Vercel

1. <https://vercel.com/new> → import this repo.
2. **Root Directory: `frontend`** (leave build settings on auto — Vercel
   detects Vite, runs `npm run build`, serves `dist/`).
3. Add an environment variable `VITE_API_BASE` =
   `https://<your-render-service>.onrender.com/api` (from the step above).
4. Deploy. Redeploys automatically on every push to `main`.

The frontend defaults to relative `/api` (local dev + single-server mode);
`VITE_API_BASE` points it at the hosted backend, and `CORS_ORIGINS` on the
backend allows the Vercel domain.

### Loading real FIRMS data (optional)

Download a VIIRS 375m CSV for India from
<https://firms.modaps.eosdis.nasa.gov/>, then either:

```bash
curl -X POST http://localhost:8000/api/upload-firms -F "file=@firms.csv"
```

...or drop the file at `backend/app/data/firms.csv` and restart. The banner
switches to "Live FIRMS satellite data loaded".

## API

| Method | Path | Description |
|---|---|---|
| GET | `/api/detections` | Lean list (`?source=synthetic\|firms&limit=`) |
| GET | `/api/detections/{id}` | Full detail: features, top-3, evidence, why-not, priority |
| GET | `/api/stats` | Counts by class / priority / source |
| POST | `/api/upload-firms` | Multipart FIRMS CSV upload (422 on malformed file) |
| POST | `/api/classify` | Classify a raw feature dict |

Swagger docs: <http://localhost:8000/docs>

## Plugging in real Sentinel-2 / OSM / GEE data later

The feature contract is the 24 columns of `training_data.csv` (see
`app/ml/artifacts/features.json`). Swap these files to go live:

1. **Sentinel-2 (NDVI / NBR / dNBR)** — add a Google Earth Engine fetcher
   (e.g. `app/data/sentinel2.py`) that pulls pre/post-fire S2 imagery per
   hotspot and writes `ndvi, nbr, dnbr`. Wire it in
   `app/data/firms.py::parse_firms_csv` (fill the spectral keys) or in
   `app/data/detections_store.py` at ingest.
2. **Dynamic World (land-cover probabilities)** — same GEE session:
   `built/trees/crops/water_probability` per hotspot location.
3. **OSM (industrial distances)** — replace `app/data/facilities.py`'s
   static gazetteer with live Overpass API queries (industrial
   landuse/`man_made=works` around each point) to fill
   `distance_to_industrial_m`, `distance_to_refinery_m`,
   `industrial_count_500m` and give real facility names.
4. **Real labels for training** — replace the generator with a labelled
   dataset (e.g. verified flare locations, forest-fire registers, stubble
   events) at the same path, then rerun `python -m app.ml.train_model`.
   Nothing else changes: schemas, API, calibration and SHAP all stay.
5. **Live hotspots** — replace the demo seed in
   `app/data/detections_store.py` with a scheduled FIRMS area-CSV fetch
   (the parser already handles real exports).
